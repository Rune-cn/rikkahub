# 04 · 生成循环与重试（新架构，旧 API 已删除）

## 1. 新生成架构（替代旧 GenerationLoop）

```
Settings + Conversation
      │  (app/.../data/ai/ChatRequestFactory.kt)
      ▼
ChatTurnContext(settings, assistant, model, providerSetting, conversationId,
                conversationSystemPrompt, workspaceCwd, memories, tools)
      │  createAgent(turn, messages, processingStatus)
      ▼
Pair<AgentRequest, AgentHooks>   (me.rerere.ai.agent.Agent.kt)
      │  runAgent(request, hooks)              (ai/.../agent/AgentLoop.kt)
      ▼
Flow<AgentEvent>  ── MessageUpdated(message) / Retrying(attempt) / Finished(message, reason)
```

- 聊天场景：`ChatService.runTurn(session: ConversationSession, regenerateNodeId?)` 内使用（agent 循环 + 工具循环）。
- **无会话/无 UI 的一次性生成**（子 Agent、工作流步骤）写法模板：

```kotlin
val turn = ChatTurnContext(
    settings = settings,
    assistant = assistant,
    model = model,
    providerSetting = model.findProvider(settings.providers) ?: error("Provider not found"),
    conversationId = Uuid.random(),
    conversationSystemPrompt = null,
    workspaceCwd = null,
    memories = if (assistant.enableMemory) memoryRepository.getFiles(assistant.memoryId) else emptyList(),
    tools = tools,
)
val (request, hooks) = requestFactory.createAgent(turn, messages, MutableStateFlow(null))
runAgent(request, hooks).flowOn(Dispatchers.IO).collect { event ->
    when (event) {
        is AgentEvent.MessageUpdated -> { /* 流式输出：event.message */ }
        is AgentEvent.Retrying -> Unit
        is AgentEvent.Finished -> { /* 最终文本 event.message.toText() */ }
    }
}
```

- 不要再用 `GenerationChunk` / `GenerationLoop.generateText`（已删除）。

## 2. 重试（RetryPolicy）

- `ai/.../agent/Retry.kt`：`RetryPolicy(maxRetries, initialDelay, retryOn)`，`withRetry` 内建指数退避。
- `ChatRequestFactory.retryPolicy()`（app 侧）已接入 fork 的可配置重试：
  - `enableAutoRetry=false` → NONE；否则构造 RetryPolicy：
    - `maxRetries = rateLimitRetryCount`
    - `backoff`：`rateLimitRetryMode`（FIXED / EXPONENTIAL_BACKOFF / JITTER）映射为 `ai/.../agent/Retry.kt` 的 `RetryBackoff` 枚举——FIXED=固定 `initialDelay`；EXPONENTIAL_BACKOFF=指数退避（默认，1s/2s/4s…）；JITTER=Full Jitter（指数上限 `[1ms, 上限]` 内随机）。
    - `retryOn`：停止关键字优先；IOException 或（限流开关开 && 状态码/关键字命中）才重试。
- 若要调整间隔策略的实现，改 `ai/.../agent/Retry.kt`（`withRetry` 里的 `wait` 计算）+ `Settings.kt`（`RetryMode` 枚举，见 03）。

## 3.5 主上下文中的子 Agent 展示消息（踩坑）

- 子 Agent 消息节点写进主对话只用于展示，**不要发给主模型**：
  - `Conversation.mainMessages`（`data/model/Conversation.kt`）＝ `currentMessages` 过滤 `isSubAgentDisplayMessage()`（`modelSnapshot.modelId == "sub-agent"`）。
  - `ChatService.runTurn()` 组装 `history`、`updateMainContext`、`replyNodeId` 计算都基于过滤后的主消息/跳过子 Agent 节点；压缩与标题/建议生成用 `mainMessages`。
  - 否则：① 模型把子 Agent 的话当成自己说的（上下文污染）；② 主 Agent 回复被 upsert 进子 Agent 节点（\"子 Agent 对话框里出现主 Agent 输出\"）。
- **回复节点定位（重要踩坑）**：`replyNodeId` 决定这一轮回复写进哪个消息节点。正确语义是：
  - 只有「过滤子 Agent 展示消息后的最后一条」是主 Agent 的 ASSISTANT 消息，才复用**它所在的节点**继续写；
  - 用户再发新消息后（末尾是 USER）必须**新建节点**（`Uuid.random()`），否则新回复会被写进上一轮回复节点里，表现为「每次对话都在旧回复基础上继续改」。
  - 实现要点：过滤后的 `history` 与 `nodes` 索引不再一一对应，定位节点必须用 `allHistory.indexOfFirst { it.id == lastMainAssistantMessage.id }` 找回原始索引再取 `nodes[i].id`；不要用 `indexOfLast { role == ASSISTANT }` 全局找最后一个助手消息——那会把用户再次提问后的回复也写进旧回复节点。
- 判断扩展函数：`data/model/Conversation.kt` 底部 `UIMessage.isSubAgentDisplayMessage()`（internal，跨包用需 import）。
