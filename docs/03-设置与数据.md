# 03 · 设置与数据（新增字段规范）

## 1. 设置系统的三个文件（改设置必看）

| 文件 | 职责 |
|---|---|
| `app/.../data/datastore/Settings.kt` | `Settings` 数据类与各个子模型（ToolAutoAllowSetting / SubAgentSetting / NetworkSetting / DisplaySetting …），全部 `@Serializable` |
| `app/.../data/datastore/SettingsFields.kt` | `SETTINGS_FIELDS: List<SettingsField<*,*>>` 注册表：key ↔ 属性 ↔ 编码/解码。**新增字段必须在这里注册** |
| `app/.../data/datastore/PreferencesStore.kt` | `SettingsStore`：`settingsFlow`（读）、`update(fn)`（写，内存权威 + 落盘）、`awaitLoaded()`、`launchCountFlow` |

## 2. 新增一个设置字段的标准步骤

1. `Settings.kt`：在数据类加 `val xxx = 默认值`（@Serializable）。
2. `SettingsFields.kt` 的 `SETTINGS_FIELDS` 里加一行：
   - 基本类型：`plain(KEY, Settings::xxx) { copy(xxx = it) }`
   - JSON 对象/列表：`json(KEY, Settings::xxx) { copy(xxx = it) }`
   - UUID：`uuid(KEY, Settings::xxx) { copy(xxx = it) }`
   - 特殊编码：直接 `SettingsField(key, prop, set, encode = …, decode = …)`
3. `PreferencesStore.kt` `SettingsStore.companion` 里加 `val KEY = stringPreferencesKey("xxx")`（或 int/boolean）。
4. 读：`settingsStore.awaitLoaded().xxx` / `settingsFlow`；写：`settingsStore.update { it.copy(xxx = …) }`。
   **不要**用"整份 snapshot 写回"（上游已改为内存权威，整份写回会覆盖并发修改）。

## 3. 已注册的 fork 字段

| 字段 | key | 类型 | 用途 |
|---|---|---|---|
| toolAutoAllowSetting | tool_auto_allow_setting | JSON(ToolAutoAllowSetting) | 自动允许总开关 + disabledTools |
| subAgentSetting | sub_agent_setting | JSON(SubAgentSetting) | 子 Agent 默认模型（`defaultModelId`；`defaultInheritContext` 共享上下文字段 2026-10-31 已移除） |
| enableSubAgent | enable_sub_agent | Boolean | 多 Agent 总开关 |
| chatDrafts | chat_drafts | JSON(Map<String,String>) | 输入框草稿 |
| workflows | workflows | JSON(List<Workflow>) | AI 工作流 |

NetworkSetting 内：enableRateLimitRetry / rateLimitRetryMode / rateLimitRetryCount / retryableStatusCodes / retryKeywords / stopRetryKeywords（重试相关，见 04）。

## 4. 数据层注意

- 会话（Conversation）消息在内存 + `session.flush()` 落库；**不要**绕开 ConversationSession 直接改库。
- 工作流/草稿/子 Agent 相关的持久化都走 Settings（上面表格），不需要另建表。
- 迁移：上游有 `data/datastore/migration/PreferenceStoreV*Migration`，加字段通常不需要迁移（有默认值），删除字段才需要。
