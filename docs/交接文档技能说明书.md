# 交接文档（handoff docs）技能

目标：让"下一次开发（人或 AI）"读文档即可接手，不靠记忆、不重复踩坑。

## 一、体系结构（标准模板）

在仓库根目录建主文档 + 一个文档目录，代码逻辑按模块**单独成文件**：

```
AI_DEVELOPMENT.md            # 主文档：概况 + 当前情况 + 索引 + 铁律 + 给下一会话的清单
docs/                        # 逻辑文件目录（每个模块/主题一个文件）
  01-架构总览.md
  02-<功能模块>.md
  03-...  （按需 01、02、03…）
```

主文档必须包含：
1. **项目概况**：仓库地址、包名/语言/框架、模块划分（表格）
2. **当前开发情况**：版本号、同步/构建状态、已完成事项、**已知待办与注意事项**
3. **代码逻辑索引**：表格列出 docs/ 下每个文件 → 内容说明（主文档链接过去）
4. **给后续 AI 的开发清单**：动某类代码前先读哪个文件
5. **铁律**（原样强调）：任何修改（代码/界面/行为/构建/发布）都必须同步更新主文档与对应逻辑文件

docs/ 逻辑文件内容要点：文件位置（真实路径）+ 关键逻辑 + 踩过的坑 + "不要做什么"。引用代码时写清楚路径，让人能直接打开。

## 二、如何更新（每次修改项目后必做）

1. **判断改动影响面**：
   - 改了功能/新增功能 → 更新对应模块逻辑文件（没有则新建 0n-xxx.md 并加进索引）
   - 改了设置字段 → 更新设置/数据篇（含新增字段规范）
   - 改了生成/工具/重试 → 更新对应篇
   - 改了构建/发布/版本号 → 更新构建发布篇
   - 改了 UI/交互/约定 → 更新 UI 约定篇
   - 做了上游同步 → 更新同步状态（基线 commit、新坑）
2. **更新"当前开发情况"**：版本号、构建结果、待办（完成项移除、新待办补上）。
3. **维护索引表**：新增/删除文件时同步改主文档表格与链接。
4. **只写行为与逻辑，不写密钥/PAT/签名**（写"secrets 名"即可）。

## 三、校验清单（更新完必须自查）

- [ ] 主文档"当前开发情况"是最新状态
- [ ] 索引表与 docs/ 实际文件一一对应，链接有效
- [ ] 每个改动点都能追到某个逻辑文件里的一句话/一段
- [ ] 没有残留指向旧目录的链接（如目录改名后）
- [ ] 铁律段保持存在

## 四、本机仓库现状（Rune-cn/rikkahub）

- 主文档：`AI_DEVELOPMENT.md`
- 逻辑目录：`docs/`（01 架构总览、02 fork 定制功能、03 设置与数据、04 生成循环与重试、05 构建与发布、06 上游同步、07 UI 交互与代码约定）
- 用户要求：**每次修改项目都必须同步更新这些文档**；文档为中文；不在文档里写密钥。
